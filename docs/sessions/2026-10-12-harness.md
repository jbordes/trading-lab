## Interpretaciones

- La bitácora debe representar el trabajo del día aunque no haya cambios de código, estrategias o datos versionados.
- Acoplarla a una feature produciría una historia incompleta y conflictos innecesarios al integrar ramas.

## Decisiones

- Las features se desarrollan en ramas y se integran mediante pull request con merge humano.
- Las bitácoras diarias son canónicas en `main` y se publican mediante commits exclusivos.
- Solo se pueden crear o actualizar entradas cuya fecha inicial corresponda al día actual en `Europe/Madrid`.
- Las entradas de días anteriores son inmutables; cualquier corrección posterior se registra en el día corriente.
- El archivo normal de cada jornada es `YYYY-MM-DD.md` y reúne todos sus temas mediante bloques horarios o subtítulos.
- El sufijo `-tema` solo se admite cuando exista una razón excepcional para dividir deliberadamente la jornada.
