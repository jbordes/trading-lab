### Evidencia inicial del experimento

- Se creó desde `main` la rama corta `feature/mt5-telemetry-collector-spike`.
- El spike incorpora fuente MQL5 auditable, receptor Python separado en loopback,
  contrato `mt5-telemetry-v1`, buffer acotado e idempotente y guardas del harness.
- El receptor autentica ingestión, limita payloads, contabiliza secuencias faltantes
  y no entrega el último payload mediante su endpoint público de salud.
- El dashboard conserva su servidor read-only y continúa rechazando `POST`.
- El `.ex5` generado solo para comprobar compilación fue eliminado y no se versionó.

## Interpretaciones

- El colector push puede complementar la API Python por topología, eventos y
  separación entre VPS; el spike todavía no demuestra una brecha funcional de la API.
- Mantener el receptor separado evita que la captura amplíe accidentalmente la
  superficie del dashboard visible.

## Decisiones

- ADR-0003 acepta un experimento reversible: terminal demo, endpoint loopback,
  memoria acotada, fuente `.mq5` propia y ninguna función de trading o comando remoto.
- No habrá endpoint público, persistencia productiva ni instalación en la VPS del
  socio antes de comparar el colector contra la fuente Python.
