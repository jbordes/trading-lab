### 22:30 — Inicio de jornada

- Se completaron y documentaron las revisiones profundas de performance y seguridad del sistema.

## Hechos y evidencias

- Se cerró el ciclo de revisión profunda posterior al PR #23: errores y bugs,
  performance y seguridad quedaron analizados y documentados.
- Las mediciones sintéticas mostraron que el inspector completo escala con el
  tamaño de SQLite y puede competir con el escritor mientras se mantenga el
  journal en modo `delete`; la consulta de secuencias también requiere ordenar
  mediante una estructura temporal.
- La revisión de seguridad confirmó controles existentes en el receptor
  (autenticación Bearer, límites de tamaño y conexiones, validación estricta y
  asociación de fuentes), además de los controles de solo lectura del EA.
- También identificó tres riesgos prioritarios: dashboard local sin
  autenticación ni validación de `Host`, reenvío del encabezado de autorización
  si el cliente sigue una redirección y servidor del dashboard sin límites de
  conexiones ni tiempo de espera por socket.
- El informe fue incorporado a `main` mediante el PR #24, merge `cc2f1b8`.

## Interpretaciones

- El piloto local conserva una superficie razonable mientras permanezca
  restringido a loopback, pero no está preparado todavía para exponerse por red
  o Internet. Antes de ese cambio será obligatoria una capa de acceso autenticada.
- Los problemas de performance no bloquean el volumen actual, aunque el diseño
  necesita evitar inspecciones históricas completas y contención con la captura
  antes de que crezcan los datos.

## Decisiones

- Mantener el informe como línea de base y no implementar correcciones dentro
  del mismo cambio documental.
- Priorizar, cuando se retome la implementación, el rechazo de redirecciones del
  cliente y los límites del servidor; agregar validación de `Host` ahora y
  autenticación completa antes de cualquier acceso remoto.
- Conservar la revisión integral cada seis PRs fusionados; el PR #24 inicia el
  siguiente ciclo de conteo.

## Validaciones

- La rama documental pasó la validación completa: 25 pruebas del harness, 159
  pruebas de producto, formato y lint.
- Las pruebas de seguridad y performance usaron datos, tokens y servidores
  sintéticos. No se modificaron MT5, credenciales, bases operativas ni servicios
  del piloto.
